Scenario

-

Open loop is a diagnostic mode, not an operating one: the plant trips on reactor pressure after about three hours. The IDV(12) forcing is what temain_mod.f does, and it is why every published dataset longer than eight hours carries that disturbance; turning it off departs from every number in the literature. Leaving the trip switch off is what teprob.f does, freezing the plant and continuing to report.

Share

The whole scenario lives in the fragment, so a link reproduces a run exactly rather than describing it. Only fields that differ from the baseline are written, which is why the default link is just #.

A packed row is [hours, XMEAS(1..41), XMV(1..12)]. The labels come from tepsim_core::variables, which the core checks against the teprob.f header table. XMEAS(23..41) are analyser readings that hold their value between reports, so they are drawn as steps.

Disturbances

The twenty IDV flags, read out of tepsim_core::FAULTS. Toggling one restarts the run from step zero. A simulation takes its scenario at construction and the bindings decline to invent a side door the native API does not have, because a run reachable only through the browser is a run nobody can reproduce. The three sticking faults widen a valve dead band and touch no equation, so in an open-loop run they do nothing.
